**W02 Implemented Grounding Behavior:**
* **Empty/Missing SIIS:** When the extraction engine (`ColdPathExtractionEngine`) evaluates an empty SIIS payload, it returns an empty `ContextDeeplinkResponse(contexts=[])`. The previously hardcoded fallback steps (`"General Device Support", "Check Samsung device settings"`) have been explicitly removed.
* **Ungrounded Candidate Responses:** An extracted response from a candidate LLM whose generated step groups completely fail grounding checks will result in the action being explicitly dropped rather than inventing a replacement fallback instruction.
* **Contradiction Implementation Boundaries:** Refined the deterministic W02 contradiction checker strictly to reject explicit and contextually-aligned polarities (e.g., enable vs. disable; turn on vs. turn off). By evaluating token overlap on a per-sentence basis, unrelated statements (e.g., turning off Wi-Fi) do not falsely reject instructions for different targets (e.g., turning on Bluetooth).
* **Prompt Injection Validation:** Validated that a simulated injected action generated by an underlying LLM, which lacks sufficient semantic token grounding evidence in the SIIS text, is strictly rejected by the grounding threshold logic.

**Explicit Limitations:**
* The token-overlap validation in the `GroundingChecker` represents the strict boundary of W02 logic. It effectively validates grounded steps but does *not* constitute full semantic entailment processing or universal arbitrary semantic contradiction defenses.
* The prompt injection simulated test in `test_prompt_injection_in_siis` specifically validates that the grounding check reliably rejects ungrounded steps generated from injections; this does *not* serve as or establish comprehensive prompt-injection protection.
